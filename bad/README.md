# БАД — воспроизводимое решение

Классификация карточек категории «БАД»: относится ли фактически продаваемый товар
к категории. Метка 1 = товар действительно БАД = вердикт «не бан».

Итог — ансамбль из пяти членов с мажоритарным голосованием **3 из 5**:
четыре дообученных энкодера и Qwen3.5-4B в режиме few-shot, пороги у всех 0.5.

## Протокол валидации

Зафиксирован и не менялся между экспериментами:

1. оставить `category == "БАД"`;
2. **`drop_duplicates(["name","description"])` до сплита** — 7469 строк → 5565;
3. `StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=42)`,
   `y = label`, `groups = md5(description)` — одинаковое описание не попадает
   в разные фолды;
4. метрика — `f1_score(y_true, y_pred)`, binary, `pos_label=1`, как у организаторов.

Порог выбирается **вложенно**: на остальных фолдах, применяется к текущему.
Обычный «лучший порог по всему OOF» оптимистичен, все выводы сделаны по вложенному.

Весь протокол — в `src/cv.py`, руками его повторять не нужно.

## Ключевая идея: evidence-текст

Не влезает всё описание, поэтому в модель идёт не начало текста, а окна вокруг
маркеров БАД («БАД», «биологически активная добавка», «dietary supplement», …).
`src/text.py`, функция `evidence(name, description, head=400, radius=140, budget=1600)`:
берёт первые `head` символов и вокруг каждого найденного маркера окно `±radius`,
всего не длиннее `budget`.

Это дало **+0.022 F1** на той же модели против обрезки по началу — самый крупный
одиночный выигрыш во всём решении.

## Воспроизведение

Нужен `data/data.csv` (схема описана в `data/README.md`) и GPU. Зависимости
устанавливаются из корня репозитория командой `pip install -e .`.

### 1. Валидация одиночных моделей

```bash
python -m src.train_enc --model ai-forever/ru-en-RoSBERTa --text ev \
  --head 400 --radius 140 --budget 1600 --max_len 512 \
  --epochs 4 --lr 2e-5 --bs 16 --accum 2 --head_type cls_mean --name rosb-ev-clsmean
```

Точные команды всех членов — в `jobs_train.txt`. Скрипт сам делает дедуп, строит
фолды, пишет OOF в `runs/<name>/oof.npy` и печатает AUC, F1@0.5 и вложенный F1.

Флаг `--early_stop` считает F1@0.5 после каждой эпохи, оставляет лучшую и печатает
моду и медиану лучших эпох по фолдам — это и есть число эпох для фул-трейна.

### 2. Qwen как отдельный член

```bash
python -m src.llm_probe --model Qwen/Qwen3.5-4B --text ev --fewshot \
  --max_len 1024 --bs 8 --out runs/qwen_fewshot_oof.npy
```

### 3. Подбор ансамбля

```bash
python -m src.blend_search --spec specs/spec_es5_vote3.json
python -m src.stack                 # вложенный порог, стек, GBM поверх OOF
```

Итоговая конфигурация — `specs/spec_es5_vote3.json`.

### 4. Финальное обучение на всех данных

```bash
python -m src.fit_final --spec specs/spec_es5_vote3.json --out submit/artifacts
```

Кладёт в `submit/artifacts/<имя-члена>/` веса, токенизатор и `head_config.json`,
плюс `ensemble.json` — ровно то, что читает инференс. Frozen Qwen не копируется
и не обучается: production загружает его отдельно.

### 5. Проверка пути инференса

```bash
python -m src.check_infer --artifacts submit/artifacts --data data/data.csv
```

## Инференс

`inference/` — код, который едет в сабмит; от `src/` не зависит.

- `bad_predictor.py` — `BadPredictor(artifacts).predict(df)` → `(вероятности, метки)`.
  Член, который не загрузился, выбрасывается из голосования, а порог голосов
  опускается до числа выживших: потерять один голос лучше, чем весь сабмит.
- `heads.py` — `PooledClassifier`: `AutoModel` + конкатенация CLS и masked-mean +
  линейный слой на 1 выход.
- `text.py`, `feats.py` — та же очистка и evidence, что при обучении.
- `comments.py` — комментарий к вердикту, длина держится в 50..300 символов.

Веса энкодеров грузятся в fp16 — ровно в том, в чём сохранены. Через bf16 не
конвертировать: у него на 3 бита короче мантисса, и пограничные карточки
перещёлкивают.

## Про разрыв OOF и лидерборда

OOF не просто завышает — он **переставляет модели местами**. Холдаут-проверка
(обучение на 4 фолдах, скоринг пятого через код сабмита) дала F1@0.5 = 0.9455
против OOF 0.9466, то есть путь инференса верен, а расхождение с лидербордом —
настоящий сдвиг распределения. Точных пересечений трейна и теста нет: лукап
менял скор на 0 вплоть до десятого знака.

Практический вывод: подбирать по OOF пороги и число эпох можно, а вот ранжировать
близкие конфигурации ансамбля — нельзя.
